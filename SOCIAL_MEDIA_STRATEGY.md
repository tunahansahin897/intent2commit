I built a Git workflow tool that addresses a problem I've experienced countless times: looking at code from 3 months ago and having no idea WHY a decision was made.

Intent2Commit works like this:

1. Before writing code, capture intent
2. Write your changes
3. On commit, it validates whether changes match intent
4. Intent is stored permanently with the commit

Example:
```
intent "improve login performance"
# ... add console.log() for debugging ...
intent commit

⚠️ Warning: logging may impact performance
Score: 65/100
```

The alignment validation is deterministic pattern matching (not AI inference):
- Keyword correlation (intent ↔ modules)
- Scope analysis
- Known anti-patterns
- Unrelated file warnings

3 months later: `intent explain <hash>` shows the original reasoning.

This is called "repository archaeology" - understanding code by understanding the human intent that created it.
